# 常见问题与排错

适用环境：ChromeOS 的 Linux 容器（Crostini）。先跑一次自检，很多问题它会直接指出来：

```bash
qq-crfix --doctor
```

## Crostini 专属问题

### QQ 里打不了中文 / ChromeOS 输入法不出现

本项目默认给 QQ 加 `--enable-wayland-ime --wayland-text-input-version=1`：ChromeOS 的输入法（crosim）只实现了 `zwp_text_input_v1`，而 Chromium/Electron 在 Wayland 下默认请求 v3，协议对不上就完全用不了。按顺序检查：

1. 确认是从应用菜单的「**QQ (CrFix)**」或 `qq-crfix` 启动的。旧 QQ 要连托盘一起完全退出；`--doctor` 的「正在运行的 QQ」会告诉你有没有注入成功。
2. `qq-crfix --doctor` 的「输入法参数」一行应为启用，「输入法协议」一行应能看到 `text-input-v1`（需要容器里装了 `wayland-utils`）。看不到说明当前不是 Sommelier 提供的 Wayland 会话，或 ChromeOS 版本不提供该协议。
3. ChromeOS 系统层面的中文输入法必须已启用。本项目不需要在容器里装 Fcitx；反过来，如果你装了 Fcitx，那走的是另一条路径，与本项目的 IME 参数无关。
4. 切换输入法的快捷键（如 Ctrl+Space）若被 ChromeOS 抢走，需要给 Sommelier 配 `SOMMELIER_ACCELERATORS` 把这些键放行到 Linux 应用；这是 ChromeOS/Sommelier 层的设置，启动器改不了。

排查时可以用 `QQ_CRFIX_IME_DISABLE=1 qq-crfix` 单独关掉这两个 IME 参数做对照（`--ozone-platform=wayland` 仍会保留）。

### 整个 QQ 花屏、显示不全、颜色错乱

Crostini 的 GPU 是虚拟出来的（VirGL / Venus），QQ 一旦走 Vulkan 渲染就会整个花屏、无法使用。因此本项目**完全删掉了上游的 `QQ_WAYLAND_FIX_ANGLE` 及全部相关功能**：不探测 Vulkan ICD、不传 `--use-angle=vulkan` / `--use-angle=swiftshader`、不设置 `VK_DRIVER_FILES`、也不做 GPU 崩溃自动回退。

如果仍然花屏：

- 确认没有手动给 QQ 传 `--use-angle=*`、`--enable-features=Vulkan`、`VK_DRIVER_FILES` 之类的参数或环境变量；
- 确认没有残留的 `linuxqq-wayland-fix`（上游启动器）在启动 QQ，两个项目不要混用；
- 花屏是 Crostini 虚拟 GPU 的已知限制，本项目没有任何「换个 ANGLE 后端就好了」的开关，不要再去找这类变量——它们已经被删除了。

### 屏幕共享 / 剪贴板 / 截图在 Crostini 下不生效

这几项是沿袭上游、精简后保留的 `LD_PRELOAD` 修复，依赖合成器提供 `ext-data-control`、`ext-image-copy-capture`、`wlr-screencopy` 等 Wayland 协议，以及 `xdg-desktop-portal` 的 ScreenCast 实现。Crostini 的 Sommelier 是否提供这些协议取决于 ChromeOS 版本，容器里通常也没有完整的桌面门户后端。`--doctor` 会逐项检查并给出结论。上游针对 KDE（KWin `ScreenShot2`）和 GNOME（portal `Screenshot`）的截图路径已整体删除，Crostini 下没有可替代的开关。

**这不影响本项目的核心目标**（原生 Wayland、ChromeOS 输入法、不花屏）。如果自检显示协议缺失，这几项在 Crostini 下就是无法工作的，请反馈你所用的 ChromeOS 版本。

## 继承的已知问题

### 使用 Easy Effects 时，QQ 一开通话/共享就崩

Easy Effects 会把新出现的音频流移到它自己的设备上，触发 QQ 音频模块里的竞态 bug。解决：在「输入」和「输出」页的排除应用里都加上 **`TRAE`**（QQ 音频流的应用名），QQ「设置 → 音视频通话」里把麦克风选成 Easy Effects Source。`--doctor` 会检查配置文件 `~/.config/easyeffects/db/easyeffectsrc`（Flatpak 版在 `~/.var/app/...`）的 `[StreamInputs]`、`[StreamOutputs]` 两节有没有 `blocklist=…TRAE…`。

### 不要同时运行其它剪贴板同步工具

本工具已经让 QQ 直接用 Wayland 剪贴板，再运行 `linuxqq-clipsync` 之类的 X11↔Wayland 同步工具没有必要：它们只同步一种格式，回写时会把 QQ 复制的表情换成纯文字。`--doctor` 会检查它。

### 截图窗口与共享边框窗口

QQ 的截图窗口按「放在桌面左上角、和整个桌面一样大」设计，本工具用 `libqq-screenshot.so` + `libqq-borderfix.so` 让它只截当前显示器、并在协议层补上标题 `QQ 截图` 请求全屏。共享时的全屏「屏幕共享」边框窗口、以及标题为「提示」的麦克风通知条，也会被 `libqq-borderfix.so` 摘掉绘制缓冲。日志里应有 `hiding 屏幕共享 border window`、`hiding QQ notification window (提示, …)`；没生效时先确认旧 QQ 已完全退出，再从「QQ (CrFix)」启动。

### 流畅度

共享画面由 QQ 单线程软件 H.264 编码，帧率由 QQ 自己的策略决定，本项目无法改善；在选择框里选**单个窗口**会更流畅。Crostini 的虚拟 GPU 上这一点更明显。

## 排错

### 日志

日志在 `$XDG_RUNTIME_DIR/qq-crfix.log`（可用 `QQ_CRFIX_LOG` 改），每次启动重新写：

```bash
grep -E 'qq-wl-portal|qq-clipbridge|qq-screenshot|qq-borderfix' "$XDG_RUNTIME_DIR/qq-crfix.log"
```

正常的输出：

```
[qq-clipbridge] ready (pid 12345, ext-data-control): QQ's clipboard is the Wayland clipboard
[qq-wl-portal] broadcast-core asked to connect fd=1, opening portal       ← 开始共享
[qq-wl-portal] portal ok: pipewire fd=82 node=127
[qq-wl-portal] device audio: report sample format 7 as float32le (5) …   ← 开启共享设备音频
[qq-borderfix] hiding 屏幕共享 border window (min 0x0 max 214748364x214748364) ← 隐藏共享边框
[qq-borderfix] hiding QQ notification window (提示, 1200x64)              ← 隐藏提示条
[qq-clipbridge] QQ copied -> Wayland: text/plain;charset=utf-8 …          ← QQ 里复制
[qq-screenshot] captured 4530x1440 root from Wayland via ext-image-copy-capture …
```

日志头部会记 `ime=on|off` 和 `clipboard=on|off`；**本项目不再记录任何 ANGLE / ICD 信息**。

AppImage 版（`linuxqq-appimage`）的内部实现检查需要 QQ 运行中：`broadcast-core.so`、`wrapper.node` 在 AppImage 的挂载目录里，`--doctor` 会从运行中主进程的 exe 定位。

### 崩溃记录

QQ 崩溃时，Bugly 的 `tomb_*.txt` 会保存到 `~/.cache/qq-crfix/crash/`（原位置会被 `linuxqq` 启动脚本清空），反馈问题时请附上。

### 症状对照

| 症状 | 原因 / 办法 |
| --- | --- |
| QQ 里打不了中文、候选框不出现 | 见上文「Crostini 专属问题」；先跑 `qq-crfix --doctor` 看 text-input-v1 |
| 整个界面花屏 / 显示不全 | 手动传了 Vulkan/ANGLE 参数，或还在用上游启动器；本项目不会选任何 ANGLE 后端 |
| 高分屏下窗口过小 / 过大 | Crostini 的缩放由 Sommelier 处理，本项目不改动缩放；必要时调整 ChromeOS 的显示缩放 |
| 提示「Wayland桌面环境暂时无法使用屏幕分享功能」 | 不是从「QQ (CrFix)」打开的 |
| 点共享没反应，栈里有 `PulseAudioWrapper` | Easy Effects，见上文 |
| 点「确定」没反应，栈里有 `ZSTD_` / `libgallium` | QQ 自带的 zstd 与 Mesa 冲突；启动器已设置 `MESA_SHADER_CACHE_DISABLE=true`，确认没被覆盖 |
| 日志里没有任何 `qq-wl-portal` / `qq-clipbridge` | QQ 没被注入（旧 QQ 没退干净），或 QQ 更新后改了实现，运行 `--doctor` |
| `compositor supports neither …` | 合成器不支持 data-control，剪贴板修复不可用 |
| QQ 里粘贴时卡几秒、什么也没粘上 | 复制那份内容的程序迟迟不交数据；QQ 粘贴最多等 3 秒 |
| `response=1` | 在 portal 选择框里点了取消 |
| 按截图键 QQ 闪退，日志里有 `X_GetImage` 的 `BadMatch` | 截图修复没有生效；正常时日志里有 `[qq-screenshot] captured …` |
| 点「确定」开始共享时 QQ 闪退，崩溃记录里是 `signal: 5 (SIGTRAP)` | 显示器坐标不从 0 开始时 QQ 算出空的窗口几何；本工具会自动处理，日志里应有 `empty-geometry fix: patched` |
| 选完屏幕对方没画面，日志里有 `no more input formats (-22)` | 合成器只给 DMA-BUF；现在会补一个 LINEAR DMA-BUF 格式 |
| 观看共享时画面花屏（横竖条纹） | **本项目已删除全部 ANGLE 后端选择功能**，Crostini 下若花屏请按上文「整个 QQ 花屏」处理 |
| 共享时仍出现全屏「屏幕共享」边框窗口 | 边框隐藏没生效：完全退出旧 QQ 再从「QQ (CrFix)」启动 |
| 「提示」麦克风通知条仍然弹出 | 同上，检查日志里的 `hiding QQ notification window` |

### 单独关掉某个修复

排查时可以在启动前设置环境变量（注入库自己的开关名称沿袭上游，没有改名）：

| 环境变量 | 关掉的修复 |
| --- | --- |
| `QQ_CRFIX_IME_DISABLE=1` | 只关 `--enable-wayland-ime` / `--wayland-text-input-version=1` |
| `QQ_WL_NATIVE_DISABLE=1` | 屏幕共享（包括共享电脑声音、共享时防闪退） |
| `QQ_WL_GEOMETRY_FIX_DISABLE=1` | 共享时防闪退 |
| `QQ_WL_DMABUF=off` | 关掉给只出 DMA-BUF 的合成器补的格式；`first` 则让它优先于共享内存 |
| `QQ_CLIPBOARD_FIX_DISABLE=1` | 剪贴板 |
| `QQ_CLIPBOARD_DEBUG=1` | 剪贴板日志多记每次向 QQ 取数据的结果 |
| `QQ_SCREENSHOT_FIX_DISABLE=1` | 截图 |
| `QQ_SCREENSHOT_PROTOCOL=ext` / `wlr` | 只用 `ext-image-copy-capture` / `wlr-screencopy` |
| `QQ_DRAWING_RECT_FIX_DISABLE=1` | 只关共享批注窗口的逻辑尺寸换算 |
| `QQ_BORDER_FIX_DISABLE=1` | 窗口修补（共享边框、截图覆盖层标题与全屏、提示条） |

例如：

```bash
QQ_CLIPBOARD_FIX_DISABLE=1 qq-crfix
```

`qq-crfix --help` 会列出启动器自己认识的变量；上表其余变量由注入库读取。
